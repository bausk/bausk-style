# Principles

These hold in every look. A look decides how they show; it does not switch them off.

**Specific over generic.** Every look is built on one real object from Oleksandr's work (a drawing
sheet, a survey map, a constructivist cover), named in its LOOK.md. When a choice is open, ask what
that object would do. "Modern, clean, premium" names a region; a reference names a point.

**Content first, chrome last.** The page exists to carry an article, a chart, a lecture or a game.
Structure (rules, labels, numbering) must say something true about the content. Decoration that
says nothing is removed.

**One accent, and it means something.** Ink and paper do the work. The accent marks what is
current, actionable or important. Colour beyond it belongs to data and to state.

**Same level, same look.** Items that are peers look identical. Differences encode data.

**Type does the hierarchy.** Size steps, weight and space separate levels; boxes, shadows and
colour fills do not.

**Real numbers, real words.** No invented metrics, testimonials or claims. Sample data says so.
Copy is specific: names, quantities, units, dates.

**Two languages, one standard.** Ukrainian and English get the same care: correct glyphs,
typographic quotes, both strings reviewed.

**Accessible by construction.** Contrast floors are tested in the build; colour is never the only
signal; focus is visible; motion is optional.

**Verified by looking.** Work is done when its screenshot at shipping size matches the specimen's
quality, not when the code compiles.

**Stable names, evolving looks.** Projects use token and component names. The values behind them
belong to the look and change with it. That is what lets a project take a new look by upgrading.
