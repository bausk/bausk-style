# bausk-style

The house style is the design brief. It is versioned: each project uses the guide, tokens and rules of the bausk-style version it has installed, so always go through the launcher below rather than reading a copy from memory.

## Steps

1. **Get the brief.** From the project directory run:

   ```bash
   <skill-dir>/scripts/bstyle brief --media <reading|dashboard|slides|pptx|figures|game|video>
   ```

   `<skill-dir>` is the directory containing this SKILL.md. The launcher finds the CLI matching the project's version (its `node_modules/bausk-style`, else the version in `bausk-style.json`, else the development checkout). The brief prints the look, the tokens, the rules in force, the project's own rules and which guide files to read next. Read the files it lists for your medium.

   If the project has no `bausk-style.json` and the work is visual, ask the user whether to set it up (`bstyle init --media <m> --agents`); do not invent a style.

2. **Build with names, not values.** Use `--bs-*` variables, the `bs-*` component classes, the Tailwind theme names, `tokens()`/`readTokens()` in JS, or `bausk_style` in Python. A missing token or component is a request for the system; say so instead of hard-coding a value.

3. **Precedence.** `must` rules and accessibility floors, then project rules, then the look, then everything else. Generic design skills (frontend-design, impeccable) and your own taste come last: they do not override the look. Put novelty only where the look names a signature.

4. **Verify.**
   - `<skill-dir>/scripts/bstyle check` must report no errors; explain any warning you keep.
   - Screenshot what you made at its shipping size (`bstyle shot <file-or-url> --width 390` and `--width 1440`; 1920×1080 for slides and video), look at it, and compare it with the look's specimen (path in the brief).
   - For web UI, also run `npx impeccable detect <url>` if the user has Impeccable.

5. **Report** which rules you could not follow and why (cite rule ids).

## Changing the style itself

Changes to colours, looks, rules or components happen in the bausk-style repository (default `~/bausk-style`), not in a project. Read its `AGENTS.md` first: palettes and released looks are frozen, and some changes need a major version.
