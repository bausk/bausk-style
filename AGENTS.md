# Working on bausk-style itself

This repository is Oleksandr Bausk's house style: tokens, looks, components, a guidebook, rules,
a CLI and an agent skill. Projects consume released versions. Read VERSIONING.md before changing
anything that a project can see.

## Layout

```
tokens/contract.json        public token names (the contract)
tokens/palettes/*.json      named colours; released ones are frozen (tokens/frozen.json)
tokens/looks/<id>/          look.json (mapping), LOOK.md (prose, DESIGN.md section order), signature.css, rules/
tokens/brands/*.json        identity and the brand's default look
components/base.css         shared components, token-driven, no literal values
guide/, rules/              the guidebook and atomic rules (front matter documented in rules/README.md)
build/                      build.mjs (dist/ + python data), test.mjs (release gate), release.mjs, lib/, emit/
specimen/specimen.mjs       one page per look with every component; also the screenshot reference
cli/                        bausk-style CLI (brief, init, sync, check, rules, looks, shot)
skill/bausk-style/          agent skill + launcher that finds the project's version
python/                     bausk_style package (data generated by the build)
fonts/                      vendored OFL fonts + fonts.json (scripts/fetch-fonts.mjs)
dist/                       generated; committed so git tags and the CDN serve it
```

## Rules for changes

- Never change a frozen palette colour or a released look's mapping. Add a colour, a palette or a
  new look id instead. `node build/test.mjs` fails otherwise.
- New token: add it to `tokens/contract.json` with a description and define it in every look
  (minor release). Removing or renaming one is a major release with a Migration entry.
- Components use only `var(--bs-*)`. No literal colours, radii, shadows or gradients in
  `components/` or `signature.css`.
- A look's LOOK.md keeps the DESIGN.md section order: Overview, Colors, Typography, Layout,
  Elevation & Depth, Shapes, Components, Do's and Don'ts.
- After any change: `node build/build.mjs && node build/test.mjs && node scripts/shoot.mjs <look>`,
  then look at `.shots/<look>-*.png`. Lint the generated DESIGN.md with
  `npx @google/design.md lint dist/design/bausk.<look>.DESIGN.md`.
- Every user-visible change gets a CHANGELOG entry; renames get a Migration line.
- Prose follows guide/voice.md and guide/anti-slop.md (this repo is checked by its own rules).

## Adding a look

1. Palette in `tokens/palettes/<id>.json` (OKLCH or hex), status `candidate`.
2. `tokens/looks/<id>/look.json` mapping every contract name; `LOOK.md` naming one specific reference
   object; `signature.css` restyling only the signature components.
3. Fonts: add to `scripts/fetch-fonts.mjs`, run it (OFL only; record the licence).
4. Build, test (contrast and colour-blind separation are enforced), shoot, compare with other looks.
